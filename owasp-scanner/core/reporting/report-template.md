# Security Scan Report Template

Use this template to generate the final consolidated report. Copy the structure below **exactly as written**. Replace **only** the `{{...}}` placeholders with actual values. Do not add, remove, reorder, or rename any sections, headings, or table columns. Do not paraphrase or restructure the template.

Each individual finding within the Findings sections **MUST** follow the finding template in `core/reporting/format.md` exactly.

## Placeholder Reference

| Placeholder | Value |
|-------------|-------|
| `{{PROJECT_NAME}}` | Name of the scanned project |
| `{{SCAN_DATE}}` | Date of the scan (YYYY-MM-DD) |
| `{{DETECTED_TECHNOLOGIES}}` | Comma-separated list of detected technologies (e.g., `Java 17, Spring Boot 3.2, Angular 17, Docker, PostgreSQL`) |
| `{{SCAN_SCOPE}}` | Exactly one of: `Full scan`, `Quick scan`, `PR review`, or `Focused on: {{DOMAIN}}` |
| `{{MODEL_NAME}}` | Name of the AI model used (e.g., `Claude Sonnet 4`, `GPT-4.1`, `Gemini 2.5 Pro`) |
| `{{MODEL_VERSION}}` | Model version or snapshot identifier (e.g., `claude-sonnet-4-20250514`). Use `Unknown` if not available. |
| `{{SCAN_DURATION}}` | Wall-clock time for the scan to complete (e.g., `2m 34s`). Use `N/A` if timing is not available. |
| `{{CRITICAL_COUNT}}` / `{{HIGH_COUNT}}` / etc. | Integer count of findings at that severity |
| `{{TOTAL_COUNT}}` | Sum of all severity counts |
| `{{KEY_RISK_SUMMARY}}` | 1–3 sentences summarizing the most critical findings |
| `{{*_FINDINGS_USING_FORMAT_MD}}` | Findings formatted per `core/reporting/format.md` template, or `No findings.` if none |
| `{{PRIORITY_*_FINDINGS}}` | Bullet list of rule IDs and one-line descriptions for that priority tier, or `None.` if empty |
| `{{CHEATSHEET_NAME}}` | One row per unique cheatsheet referenced (repeat the row) |
| `{{*_RULES}}` / `{{*_FINDINGS}}` / `{{*_STATUS}}` | Per-domain rule count, finding count, and status (`Complete` or `Skipped — not applicable`) |

## Report Format Rules

### DO

- **DO** reproduce the report heading levels exactly: `#` for the report title, `##` for top-level sections, `###` for subsections
- **DO** include the Executive Summary table in every report, even if all counts are 0
- **DO** include the Scanner Coverage table in every report
- **DO** write `No findings.` under a severity heading if no findings exist at that level
- **DO** keep all sections in the exact order shown above
- **DO** include the AI Security row in the Scanner Coverage table when the AI Security scanner was run

### DO NOT

- **DO NOT** omit any section from the template (even if empty — use the placeholder guidance above)
- **DO NOT** add extra top-level sections beyond those in the template
- **DO NOT** change the table column headers
- **DO NOT** merge severity levels (e.g., combining CRITICAL and HIGH into one section)
- **DO NOT** use a different heading for the report title (always `# OWASP Security Scan Report`)
